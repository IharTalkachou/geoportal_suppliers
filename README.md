# Система управления поставщиками Национального геопортала

Система управления поставщиками, проектами и этапами сотрудничества Оператора Национального геопортала и Поставщиков пространственных данных. 

Web-интерфейс построен на **Streamlit**, база данных — **PostgreSQL**, оркестрация — **Docker Compose**.

---

## 📖 Описание проекта
Приложение предназначено для:
- Учёта поставщиков и их контактов
- Управления проектами (реквизиты, статусы, примечания)
- Формирования состава проектов (Наборы данных → Виды сведений)
- Трекинга бюрократических и технологических этапов с авто-расчётом сроков, итераций и авто-закрытием предыдущих стадий
- Аналитики: KPI, диаграмма Ганта, прогресс-дашборды, экспорт в Excel
- Администрирования справочников (Наборы, Виды сведений, Статусы, Форматы, Периоды)

## 🏗 Архитектура и общий алгоритм работы

### 🔹 Схема взаимодействия
```
[Браузер] ↔ (HTTP/WS) ↔ [Nginx (prod)] ↔ [Streamlit App] ↔ [SQLAlchemy] ↔ [PostgreSQL]
                                                                                ↑
                                                                    [pgAdmin (GUI для БД)]
```

### 🔹 Алгоритм работы (цикл запроса)
1. **Инициализация:** При старте контейнера `app.py` создаёт `SQLAlchemy Engine` и `Session`.
2. **Рендер UI:** Streamlit выполняет скрипт сверху вниз. В зависимости от выбранной вкладки вызывается соответствующая `render_*_tab(session)`.
3. **Загрузка данных:** Все `SELECT`-запросы проходят через `config/cache.py → query_db()`, который кеширует результат на 60 секунд (или до принудительного сброса).
4. **Пользовательский ввод:** Пользователь редактирует таблицу `st.data_editor` или заполняет форму.
5. **Обработка на бэкенде:** При нажатии `Сохранить`:
   - Рассчитываются авто-значения (итерация, `planned_end`, авто-закрытие предыдущего этапа).
   - Формируются `INSERT / UPDATE / DELETE` через `session.execute()`.
6. **Фиксация и обновление:** `session.commit()` → `clear_cache()` → `st.rerun()`. Страница перерисовывается с актуальными данными из БД.

## 📄 Детальное описание файлов и функций

### ⚙️ Конфигурация и ядро
| Файл | Ключевые объекты | Назначение |
|------|------------------|------------|
| `src/app.py` | `render_project_dashboard`, `render_analytics_tab`, `render_suppliers_tab`, `render_datasets_tab` | Точка входа. Инициализирует сессию БД, управляет навигацией (табы), хранит глобальные `session_state`. |
| `config/db.py` | `get_session()`, `engine` | Создаёт `SQLAlchemy Engine` на основе переменных окружения (`DATABASE_URL`). Возвращает контекстный менеджер сессии. |
| `config/cache.py` | `query_db(sql, params)`, `clear_cache()` | Обёртка над `pd.read_sql`. `@st.cache_data` кеширует SELECT. `clear_cache()` инвалидирует кэш после COMMIT. |

### 🖥 Пользовательские вкладки (`src/ui/`)
| Файл | Главная функция | Краткое описание логики |
|------|----------------|--------------------------|
| `suppliers_tab.py` | `render_suppliers_tab(session)` | Объединяет поставщиков и контакты. Фильтр → карточка поставщика (метрики) → редактор контактов. Формы добавления в `expander`. Динамический маппинг колонок, скрытие ID. |
| `datasets_tab.py` | `render_datasets_tab(session)` | Два блока: 1) Редактор наборов данных с защитой от удаления (если используется в проектах). 2) Редактор видов сведений с зависимым фильтром по набору. Справочники форматов/периодов. |
| `project_dashboard.py` | `render_project_dashboard(session)` | Главный хаб проектов. Зависимые фильтры `Поставщик → Проект`. Карточка проекта (`st.metric`). Редактор состава проекта (`project_items`). Роутинг в `bureaucracy_tab` и `technology_tab`. |
| `bureaucracy_tab.py` | `render_bureaucracy_tab(session, project_id)` | Документарные этапы (`track_category='1. Документарный'`). Авто-итерация (`MAX+1`), авто-расчёт `planned_end` (Веха=0дн, Задача=`+duration`), авто-закрытие предыдущего этапа при вводе `actual_start`. |

## 🔄 Поток данных (Data Flow Example)
1. **UI:** Пользователь открывает вкладку `📜 Бюрократия`.
2. **Fetch:** Вызывается `query_db()` → данные берутся из кэша или БД.
3. **Edit:** Пользователь добавляет строку в `st.data_editor`, указывает `Факт. начало`.
4. **Submit:** Нажимает `💾 Сохранить этапы`.
5. **Process:** 
   - `is_new=True` → запрашивается `MAX(iteration_count)` → `iteration = max + 1`.
   - `planned_end` рассчитывается из `duration_days`.
   - Запускается `UPDATE ... SET actual_end = :start` для последней незакрытой стадии.
6. **Commit:** `session.execute(INSERT)` → `session.commit()`.
7. **Refresh:** `clear_cache()` → `st.rerun()` → UI обновляется.

## 🛡 Безопасность и оптимизация
- **Кэширование:** Все `SELECT`-запросы кешируются на 60 сек. `clear_cache()` вызывается только после успешного `COMMIT`.
- **Скрытые ID:** Первичные ключи (`*_id`) передаются в `st.data_editor`, но скрыты из UI через `column_order`. Это предотвращает случайное редактирование PK, но сохраняет целостность `UPDATE/DELETE`.
- **Транзакции:** Все изменения обёрнуты в `try/except`. При ошибке вызывается `session.rollback()`, данные не коммитятся частично.
- **Защита от удаления:** Наборы данных нельзя удалить, если они привязаны к `project_items`.
